## 2. Architecture Overview

### 2.1 Application Portals
The application is divided into three main portals, accessible from the static landing page (`src/app/page.js`):
1. **Admin Command Center** (`/admin`)
2. **Driver Field App** (`/driver`) - Built as a PWA with IndexedDB offline sync.
3. **Citizen Public Portal** (`/citizen`) - Features Web3/MetaMask integration.

*Note on Landing Page:* The landing page (`src/app/page.js`) contains hardcoded KPI stats (`24` Active Routes, `1,204` Completed Pickups). These are NOT fetched from the database.

### 2.2 Data Transport and Realtime
All data reads/writes utilize **Supabase**. The browser client is initialized in `src/lib/supabase.js`.
Realtime updates (`postgres_changes`) are actively used across the app. Examples:
- **Admin fleet monitor** (`src/app/admin/fleet/page.jsx`): Listens for `driver_profiles` updates.
- **Admin reports** (`src/app/admin/reports/page.jsx`): Listens for `CitizenReports` events.
- **Driver dashboard** (`src/app/driver/page.jsx`): Listens for `driver_profiles` updates.

## 3. Authentication & Role System

**Provider:** Supabase Auth is used exclusively.
- **Driver Role:** Enforced in `src/app/login/driver/page.jsx` via Supabase Auth and a `driver_profiles.is_approved` check.
- **Admin Role:** **NOT IMPLEMENTED** at the authentication level in the reviewed files. The `/admin` portal is accessible as a direct URL link from the landing page.
- **Citizen Role:** Citizens register/login with their wallet. However, middleware-level protection in `src/proxy.js` has the Citizen Auth Guard DISABLED (currently returns `supabaseResponse` without enforcing `user.user_metadata?.role === "citizen"`).

**Driver Approval Workflow:** 
Driver registration (`src/app/register/driver/page.jsx`) creates a profile with `is_approved: false`. Admins approve drivers via the Fleet Monitor (`src/app/admin/fleet/page.jsx`), which updates the status and auto-redirects the driver via Realtime subscription.

---

## 4. PWA and Offline Strategy

**Service Worker (`public/sw.js`):**
- Manually authored (not generated by Workbox).
- Registered in `src/app/driver/layout.jsx`.
- Uses a network-first strategy, falling back to cache. Pre-caches `/driver` and `/offline`. (Note: The `/offline` page does not currently exist in the repository).

**IndexedDB Offline Queue (`src/app/driver/page.jsx`):**
- When a driver completes a route offline, the payload is saved to `EcoRouteDB` -> `syncQueue`.
- Upon reconnecting (`onOnline` event listener), the queue is replayed: `Routes` table is updated, and `HCILogs` are inserted.

## 5. Web3 / Blockchain Integration

**Smart Contract (`src/lib/contracts/ecoToken.js`):**
- **Address:** `0x502Bd8d0be1607666Cce013D8BC39246F0733148` (Hardcoded Sepolia testnet address).
- **ABI:** Human-readable ethers v6 format.
- **Note:** The actual `.sol` source code is NOT present in this repository.

**Token Operations (`src/lib/web3.js`):**
- `rewardCitizenTokens(citizenAddress)`: Interacts with the contract to reward citizens. Triggered from `src/app/citizen/report/page.jsx` after a Supabase insert.
- `burnEcoTokens(amount)`: Calls `contract.transfer()` to send tokens to a **hardcoded** treasury/admin wallet address (`0x11bB14f887c8113E2f20963c0a447aF2f8D6DE65`), rather than a true ERC-20 burn address.

## 6. HCI Telemetry (SQA)

**Data Capture (`src/app/driver/page.jsx`):**
- Logs events to the `HCILogs` Supabase table.
- **HARDCODED WARNING:** The `clicks` field is strictly hardcoded to `1` in every insert (e.g., `src/app/driver/page.jsx` and `src/app/driver/sync/page.jsx`). It does not count actual user interactions.
- `time_taken` is accurately measured in milliseconds (`Date.now() - routeStartTs`).

**Dashboard (`src/app/admin/sqa/page.jsx`):**
- Computes Total Events, Avg Task Time, Total Clicks, and Avg Clicks/Task based on `HCILogs`.

## 7. Discrepancy & Honesty Report (CRITICAL FOR THESIS)

When writing the thesis, Claude MUST acknowledge the following limitations as part of the implementation constraints:

1. **Missing Admin Auth:** No admin authentication or access control middleware is implemented (no `/admin/login` route exists).
2. **Hardcoded Stats:** Landing page KPI stats (24 routes, 1,204 pickups) in `src/app/page.js` are hardcoded literals.
3. **Hardcoded Driver Roster:** The driver dashboard (`src/app/driver/page.jsx`) displays fictional static drivers (`DRV-002`, `DRV-003`).
4. **Hardcoded Telemetry Clicks:** `clicks` in `HCILogs` is always `1`.
5. **Hardcoded Treasury Wallet:** `burnEcoTokens()` in `src/lib/web3.js` uses a hardcoded wallet address (`0x11bB14...`).
6. **No Contract Source:** The Solidity smart contract source code is absent from the repository.
7. **No Automated Testing:** No unit tests or integration tests exist in the repository.
8. **Manual Bank Payouts:** No actual fiat bank transfer mechanism exists; `BankPayouts` is purely a request log reviewed manually (`src/app/rewards/page.jsx`).
